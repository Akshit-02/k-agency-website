## UTM and analytics

  `https://discover.kudozz.in/?utm_source=kudozz_website&utm_medium=blog&utm_campaign=discovery_content&utm_content=<slug>`
- Verified in the production build: every article's HTML contains exactly 2 Discovery links with `utm_content=<its own slug>`.
- **GA4 event:** clicks fire `discovery_blog_cta_click` through the existing `src/lib/discoveryAnalytics.ts` (the gtag loaded in `layout.tsx`), with `article_slug`, `article_title`, `cta_placement` (`mid_article` / `end_article`), `cta_label`, `destination` (the full UTM URL), `source_page`, `destination_host` and `outbound: true`. The brief names the parameter `destination_url`; the existing implementation (from batch 1) sends it as `destination`. It was left unchanged so GA4 reports stay continuous across all 80 articles. Rename it only if you also update the GA4 custom dimension. No analytics code was changed and no provider was added.
